# 技能

技能分两层。

- **说明**存在 `skills` 表里，创建时记下所属部门。名称、何时使用和正文会附在智能体的系统提示后面，模型直接阅读。一个部门能不能看见这条技能，由部门授权决定，不由创建时所在的部门单独决定。
- **脚本**是 `backend/data/skills/{技能编号}/` 下的文本文件。清单存在 `scripts_json`。模型通过函数调用点名之后，平台把这一份文件送进隔离容器执行。

勾选技能只划定范围，不会自动运行脚本。规则模型没有函数调用，只能读到说明。

新建或编辑智能体时，勾选技能会把名称、何时使用、正文和脚本文件名写入提示词末尾的「可用技能」一段。这段要求模型先对照「何时使用」判断要不要调用，再决定技能标识和脚本文件名。取消勾选会去掉这一段。这段之前的文字会保留。保存时按当时的技能说明再写一次；运行时如果技能说明已经改过，模型读到的是最新说明，仍然只有一段。函数 `skill_script` 的说明里也会列出每个技能的使用条件和脚本名。

## 谁可以改

部门能使用哪些技能，由平台管理员在新增部门时勾选，或由平台管理员和部门管理员在编辑部门时勾选。平台管理员看全部技能；部门管理员只能勾选自己已经可以使用的技能，也只能看到自己管理的部门。部门管理员不能新增部门。新建和导入的技能默认只给当前部门。其他部门要等授权之后才会在技能列表、智能体勾选和工作流里看到它。

查看已授权的技能与本部门其他列表相同。修改和删除只针对本部门创建的技能，需要构建者及以上。别的部门授权过来的技能可以查看和使用，页面上不出现编辑和删除。

可用范围有三处，后一处只影响那一次运行：

| 位置 | 保存位置 |
|---|---|
| 新建或编辑智能体 | 智能体版本的 `skill_ids_json` |
| 工作流节点 | 节点上的 `skill_ids`，执行时盖住版本 |
| 执行工作流对话框 | 同样写入节点配置，只影响这次运行 |

停用的技能不会进入系统提示，也不能被函数调用。

## 模型如何用到技能

连得上的模型走 `agent.py` 的工具循环，最多 20 轮。这一轮的工具列表由 `_tool_catalog` 组装。只要本次有已选技能，列表里就多一个函数 `skill_script`：

| 参数 | 含义 |
|---|---|
| `skill` | 技能标识，例如 `webapp-testing` |
| `script` | 脚本文件名，例如 `with_server.py` |
| `args` | 字符串参数，最多 8 个 |

请求使用 OpenAI 风格的 `tools`，`tool_choice` 为 `auto`。模型可以只回答文字，也可以返回函数调用。`gateway.complete_with_tools` 解析 `tool_calls`；有的模型把调用写在正文的 DSML 标记里，没有正式 `tool_calls` 时也会被认出来。

`_run_skill` 收到调用后做两道校验，然后才进入容器：

1. `skill` 等于本次已选且仍启用的某个技能标识。
2. `script` 出现在该技能的 `scripts_json` 里。

结果作为 `tool` 消息回到对话。同一组参数成功或失败过都不会再执行。送回模型的文本截到 1800 字，轨迹步骤保留更长的原文。

## 压缩包

`POST /api/skills/import` 接受 zip，由 `skillpack.parse_skill_zip` 解析。格式与 Cursor、Codex 的技能目录一致。

优先读路径最短的 `SKILL.md`。没有这个文件时，用包里的其他 Markdown。开头的信息块写成：

```markdown
---
name: webapp-testing
description: 何时使用这段技能
---

# 标题

正文交给模型。
```

`name` 会转成小写短横线标识。没有 `name` 时用一级标题，再没有就用所在目录名。`description` 为空时，用正文第一段。`>` 或 `|` 开头的多行说明会折成一行。解析器不执行 YAML 标签。

脚本只收 `.py`、`.js`、`.mjs`、`.java`，优先 `scripts/` 目录，同名文件只留第一份，最多 8 个。压缩包本身不超过 2MB，解压后不超过 4MB，单个文件不超过 1MB，文件数不超过 200。路径里出现 `..`、绝对路径或以点开头的目录时，整包拒绝。

手工新建走 `POST /api/skills`。编辑时「脚本文件」是下拉框，选项来自该技能已有脚本；选中后「脚本内容」显示对应正文。保存时写回这些已有脚本。

## 存储位置

脚本留在宿主机，不在容器里长期保存。一次技能一个目录：`backend/data/skills/{技能编号}/`。目录名是技能编号，文件名与 `scripts_json` 里的清单一致。容器每次执行只把这一份文件拷进 `/tmp`，跑完就删，宿主机上的文件保留。

查看或编辑已有技能时，对话框顶部显示「存储位置」。新建时还没有编号，保存之后才会出现这个目录。列表接口不带路径；`GET /api/skills/{id}` 在 `storage_path` 里返回它。技能目录位于项目内时，这是相对项目根的路径，例如 `backend/data/skills/1`。测试进程把技能写到临时目录，此时返回绝对路径。

## 容器

接口在 `core.create_app` 的启动事件里调用 `skillbox.start`，关闭事件里调用 `skillbox.stop`。

`start` 用 `backend/skillbox/Dockerfile` 构建镜像 `limen-skillbox`。基础镜像是 `python:3.12-slim-bookworm`，另外安装 Node 和 Java。然后删除同名旧容器，再拉起一只新的：

| 参数 | 作用 |
|---|---|
| `--network bridge` | 可以访问网络，便于安装依赖或调用接口 |
| `--cap-drop ALL` | 去掉全部 Linux 能力 |
| `--security-opt no-new-privileges` | 不能再提权 |
| `--read-only` | 根文件系统只读 |
| `--tmpfs /tmp:rw,nosuid,size=128m` | 唯一可写的 128MB 内存盘 |
| `--memory 512m`、`--cpus 1`、`--pids-limit 64` | 内存、CPU 和进程数上限 |

容器命令是 `sleep infinity`，不挂项目目录，也不挂 Docker 套接字。测试进程发现 `pytest` 已加载时不拉容器。本机没有 Docker 时接口仍能保存说明，执行脚本会失败。

`run_script` 的一次执行：

1. 确认本进程已经把容器拉起。没有容器就失败，不用宿主机解释器。
2. 再检查文件名，并确认技能目录里有这个文件。
3. 登记这次执行。从拷贝开始，到结束、失败或超时，总览都能看到它。
4. 在容器的 `/tmp/job-` 加随机串下建目录。执行用户是 `65534`，`HOME=/tmp`。
5. 容器内的 `tee` 从标准输入把脚本字节写入该目录。根文件系统只读，不能靠 `docker cp` 写进这块内存盘。
6. `.py` 用 `python3`，`.js` 和 `.mjs` 用 `node`。`.java` 先 `javac`，再按类名执行。参数是命令数组里的独立项，不经过 shell。
7. 最长 20 秒。标准输出和标准错误合并，最多返回 4000 字。
8. 无论成败都把这次登记标成完成或失败，并删除容器里的临时目录。宿主机上的技能文件保留。结束后的记录再保留 30 秒，供总览刷新读到。

进程退出时 `docker rm -f limen-skillbox`，可写层一起消失。进行中的登记也只活在这个接口进程里，进程退出后清空。

## 总览里的容器和脚本

运行总览在时间筛选下方显示技能容器。打开页面后每 1 秒请求一次 `GET /api/system`，只把返回里的 `skillbox` 合并进当前页。页签切到后台时暂停，回到页面立即再查。容器「运行中」只表示 `sleep infinity` 还在；脚本是否在执行看同一块里的「脚本执行」。

`skillbox` 里和容器本身有关的字段：

| 字段 | 含义 |
|---|---|
| `state` | `running`、`exited`、`created`、`dead`、`paused`、`missing`、`unavailable` |
| `started_at` | 容器启动时间 |
| `network`、`memory`、`cpus`、`read_only` | 网络、内存上限、CPU 和根文件系统是否只读 |
| `python`、`node`、`java` | 三种解释器的版本。只在容器换新时进容器查一次 |
| `error` | 容器没起来或检查失败时的原因 |

`skillbox.jobs` 包含正在执行的脚本，以及结束后 30 秒内的脚本。相加这类脚本通常不到一秒，若只在执行当下返回，每秒一次的刷新会错过。`script_running` 仅在仍有 `state=running` 时为 true。列表为空时页面显示「当前没有脚本在执行」。有记录时标成「正在执行」「刚刚完成」或「刚刚失败」，并写出技能名称和文件名。一条记录的字段：

| 字段 | 含义 |
|---|---|
| `id` | 这一次执行的编号，也是容器里临时目录名的后半段 |
| `skill_id` | 技能编号 |
| `skill_name`、`skill_key` | 按编号补上的名称和标识。技能已删除时为空 |
| `script` | 文件名，例如 `add.py` |
| `state` | `running` 正在执行，`finished` 刚刚完成，`failed` 刚刚失败 |
| `started_at` | 开始时间，Unix 秒 |
| `ended_at` | 结束时间。仍在执行时为空 |

同时执行多份脚本时，列表里会有多条。参数不出现在总览上。
