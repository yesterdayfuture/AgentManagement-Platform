# 构建自主决策的智能体

固定步骤工作流按连线依次把上一步的输出交给下一步。自主调度由**调度者先调用模型**，阅读用户问题与全体成员职责，拆成子任务 JSON，再决定每一步由调度者自己执行还是分发给下游智能体。

被分到任务的智能体仍走自己的 `execute_agent`：计算、检索、列目录、写入和对话，按**该条子任务的文字**重新判断。

## 两种执行方式

保存工作流时，执行方式写入 `definition.kind`。`run_workflow` 先看这个字段。

| | 固定步骤 `agents` | 自主调度 `autonomous` |
|---|---|---|
| 入口 | `run_workflow` → `_run_agent_graph` | `run_workflow` → `_run_autonomous` |
| 节点顺序 | 沿连线走，没有入边的节点是起点 | 先规划完整列表，再按列表下标执行 |
| 交给智能体的话 | 上一步的输出；第一步是用户原文 | 这一条子任务的原文（可选附带上一步参考） |
| 日志事件 | `调用`、`暂停`、`停止`、`继续` | `规划`、`自己执行`、`分发`、`暂停`、`停止`、`继续` |
| 连线的含义 | 执行顺序 | 调度者可以分发给谁 |

两种图的节点类型都是 `agent`。所以 `run_workflow` 必须先判断 `kind == "autonomous"`，不能只看节点类型。

界面在 `frontend/src/views/Workflows.vue`。执行方式选「自主调度：先拆子任务，再自己做或分发」时，`definitionOf()` 把 `kind` 写成 `autonomous`。

## 在界面上建一个

1. 在智能体页准备好调度者和下游，名称尽量好认（规划结果里的 `agent` 必须是这些名称之一）。
2. 给调度者勾选它自己要调用的工具。自己执行「计算 19*7」时，调度者的版本里必须有 `calculator`。下游只处理对话时，可以不勾工具。
3. 打开工作流，新建，执行方式选自主调度，保持启用。
4. 先把调度者拖进画布。保存时 `entry` 是节点数组的第一项，也就是最先拖进去的智能体。界面上标「调度」的是没有入边的节点。先放调度者，这两处才是同一个智能体。
5. 再拖入下游智能体。从调度者右侧端口拖到下游节点，松开后出现连线。点击连线可去掉。
6. （可选）点节点「配置」，填写该节点提示词与工具/知识库等。节点提示词会影响规划花名册里的职责文案，以及该节点真正执行时的系统提示。
7. 保存并试运行，例如「先规划大纲，再让写作者起草，最后审稿人核对」。
8. 在执行记录里看第一条「规划」日志：`output` 是子任务 JSON；随后是「自己执行」或「分发」。

没有从调度者连出的边时，画布上其余智能体都会成为候选。连出边之后，只有这些下游能被点名分发。

停用的工作流不能执行，也不能继续。

智能体如果在输出里用 `<<<FILE 相对路径>>>` 和 `<<<END>>>` 包住文件，或在 Markdown 代码块的语言后面写上相对路径，执行记录会收集这些文件。查看执行详情时可以下载项目压缩包，接口是 `GET /api/workflow-runs/{id}/archive`。路径不能包含 `..` 或隐藏目录。

## 定义长什么样

`POST /api/workflows` 的 `definition`：

```json
{
  "kind": "autonomous",
  "entry": "lead",
  "nodes": [
    {"id": "lead", "type": "agent", "agent_id": 1, "prompt": "可选：调度者在花名册中的职责"},
    {"id": "hand", "type": "agent", "agent_id": 2, "prompt": "可选：下游在花名册中的职责"}
  ],
  "edges": [{"src": "lead", "dst": "hand"}]
}
```

`agent_id` 必须属于当前空间。`entry` 指向调度者节点。`edges` 只表示分发候选，不表示固定顺序。`prompt` 等节点配置可选。

## 规划提示词：默认携带全员身份与职责

文件：`backend/app/services/runtime/workflow.py`（`_plan_with_model`、`_duty`、`_plan_tasks`）。

**会。** 规划阶段系统会自动把「调度者 + 全部候选子节点」的身份与职责拼进发给模型的 user 消息。这段**花名册由平台注入，工作流编辑界面不能改模板、也不能关掉**。节点上的「提示词」只影响花名册里每人的职责文案（以及后续执行该节点时的系统提示），**不会替换**下方固定的规划 system 指令。

### 职责文案从哪来（`_duty`，约 180 字）

1. 优先：该节点配置里的「提示词」
2. 否则：该智能体最新版本 `system_prompt` 的**第一行**

### 完整规划输入（有可用非 rules 对话模型时）

**System（固定，不可在界面修改）：**

```text
你是工作流调度者。阅读用户的问题，以及每位成员的职责，把问题拆成可执行的子任务并指定负责人。只根据问题需要决定拆几步、先后和由谁做，不要因为句子里出现某个词就机械分配。负责人必须是下面列出的名称之一。某一步适合自己完成时，负责人填调度者的名称。后一步需要前一步结果时，needs_prior 为 true。只输出 JSON，不要解释。格式：{"tasks":[{"title":"具体要做的事","agent":"成员名称","needs_prior":false}]}
```

**User（系统拼装；花名册结构固定）：**

```text
成员：
- {调度者名称}（调度者，可自己执行）：{职责}
- {子节点A名称}：{职责}
- {子节点B名称}：{职责}

用户问题：{本次运行输入}
```

示例（调度者「项目调度」、下游「后端开发」「前端开发」）：

```text
成员：
- 项目调度（调度者，可自己执行）：你是自主调度的调度者。阅读本次任务和各成员职责，决定拆成哪些子任务、由谁完成。
- 后端开发：负责 API 与数据模型，输出接口清单与实现要点。
- 前端开发：负责页面与交互，输出页面结构与组件说明。

用户问题：做一个学生信息管理系统，前后端分开推进。
```

### 与「总节点 / 调度节点提示词」的关系

| 内容 | 是否默认带全员信息 | 界面能否改 |
|------|-------------------|------------|
| 规划用 System | 否（固定调度指令） | 否 |
| 规划用 User 花名册 | **是**（调度者 + 全部候选） | 结构否；每人职责可间接改 |
| 调度节点「提示词」 | 只作调度者在花名册中的职责 | 可改 |
| 子节点「提示词」 | 只作该成员职责，并在分发执行时生效 | 可改 |

候选范围：优先「从调度节点连出去的下游」；没有连线时，用图中除调度者外的其余智能体节点。

### 规划模型怎么选（`_planning_model`）

优先调度者版本钉住的、已授权、已启用、非 `rules` 且额度未满的模型；否则取本部门已授权非 `rules` 里更便宜的可用模型。**规则模型不会用于规划。**

### 规划结果 JSON

模型应只输出类似：

```json
{
  "tasks": [
    {"title": "梳理后端数据模型与 API", "agent": "后端开发", "needs_prior": false},
    {"title": "根据接口设计前端页面", "agent": "前端开发", "needs_prior": true}
  ]
}
```

解析后写入计划项：`title`、`agent_id`、`agent_name`、`decision`（负责人是调度者则为「自己执行」，否则「分发」）、`use_prior`（来自 `needs_prior`，且不是第一条时才可为真）。最多采纳 8 条。`agent` 必须是花名册里的名称。

### 无可用对话模型时的兜底（`_plan_without_model`）

此时**不发**上述规划提示词，改用规则：

1. `_split_clauses` 按编号行 / 换行分号 /「然后」「并且」「同时」切开用户句。
2. 子句文字里出现候选 `name`（更长优先）或 `key` 则分发；否则调度者自己执行。

正常有 DeepSeek 等模型时，以模型规划为准。

入口函数：`_plan_tasks` → 先 `_plan_with_model`，失败再 `_plan_without_model`。

## 执行：`_run_autonomous`

同文件。`run_workflow` 在空间 token 额度未超限、且 `definition.kind == "autonomous"` 时进入它。操作者执行前工作流须为已发布（`release=published`）；构建者可测草稿。

1. 只保留 `type == "agent"` 的节点。没有这种节点时拒绝，提示「工作流没有可调度的智能体」。
2. `_entry_node` 取调度者：`entry` 在节点里就用它，否则用没有入边的节点。
3. `_person` 读取该智能体。不属于本空间则拒绝。
4. 候选来自调度者连出的边。没有这种边时，用除调度者以外的全部智能体节点。
5. 新运行调用 `_plan_tasks`，写入一条 `event` 为「规划」的日志。`output` 是计划的 JSON。游标 `cursor` 从 `"0"` 开始。
6. 按游标取出子任务，对 `agent_id` 调用 `execute_agent`。默认 `message` 是子任务标题；若 `use_prior` 且已有上一步产出，会附带最近参考材料（截断）。
7. **执行阶段不再注入全员花名册**；各节点使用自己的系统提示 + 节点配置（提示词/工具/知识库/MCP/技能）。
8. 日志 `event` 使用计划里的 `decision`（「自己执行」或「分发」）。运行输出追加一行：`决策 · 智能体名：结果`。
9. 该步状态不是 `completed` 时，整次运行停在这个状态。高风险写入挂起后，后面的子任务不会继续。
10. 全部完成后状态为 `completed`，游标清空。

继续运行时，`_saved_plan` 从日志里找「规划」并还原列表，不按新消息重新规划。

## 子任务里智能体还会再决策

分发只决定谁来做。做什么仍由 `execute_agent` 决定。连得上的模型进入工具循环；规则模型才按 `classify_intent` 做下面这张表：

| 子任务文字 | 意图 | 需要该智能体开放的工具 |
|---|---|---|
| 含「计算」或算术式 | calculate | calculator |
| 含「列出文件」「哪些文件」「文件夹」「目录」 | list | files.list |
| 含「知识」「规定」「退款」「文档」 | retrieve | knowledge.search |
| 含「转账」「付款」「写入」「发送」「删除」 | write | ledger.transfer |
| 含「转交」或「专员」 | delegate | 智能体自己的子智能体配置，只转一层 |
| 其余 | chat | 无。规则模型会回系统提示的第一句 |

「退款」会判成检索。不要用带「退款」的句子去触发一个只负责对话的下游，除非那个下游开放了 `knowledge.search`。

智能体配置里的子智能体转交，和这里的「分发」不是一条路径。分发看的是工作流画布上的节点和名称；转交看的是消息里的「转交」「专员」以及智能体版本里的子智能体。

## 暂停、停止、继续

执行页的按钮写在进程内的 `RUN_CONTROL`。每完成一条子任务，若后面还有任务，`_await_control` 最多等 0.8 秒，看有没有暂停或停止。

- 暂停：状态 `paused`，游标停在下一条尚未执行的下标，日志事件「暂停」。
- 停止：状态 `stopped`，日志事件「停止」。
- 继续：`POST /api/workflows/{id}/resume` 读回原计划，日志先写「继续」，再从游标执行。

接口也可以在运行时带 `pause_after`。完成这么多条子任务后主动暂停。测试 `test_autonomous_workflow_splits_and_assigns` 用 `pause_after: 1` 停在第一条「自己执行」之后，再继续，最后一条日志是「分发」给接待。

## 和固定步骤对照着改

固定步骤在 `_run_agent_graph`：

- 游标是节点 id，不是子任务下标。
- 每步 `message` 使用 `carry_text`，第一步是用户原文。
- 走完一条出边后进入下一个节点，最多 8 步；同一节点出现超过两次会熔断。
- 日志事件是「调用」。

要把固定流转改成自主调度，不需要换节点类型。把 `kind` 改成 `autonomous`，并保证 `entry` 是调度者。已保存的固定步骤工作流保持 `kind` 为 `agents` 时，行为不变。

若工作流是从「模型问答 → 生成工作流」起草的，模型输入与审批流程见 [ask-workflow.md](ask-workflow.md)。

## 想改规划行为时改哪里

| 目标 | 改哪里 |
|------|--------|
| 规划 system / 花名册拼装 | `_plan_with_model` |
| 每人职责截取规则 | `_duty` |
| 规划用哪个模型 | `_planning_model` |
| 解析模型 JSON | `_read_plan` |
| 无模型时的标点拆分与按名匹配 | `_split_clauses`、`_plan_without_model` |
| 规划入口与回退顺序 | `_plan_tasks` |

`_run_autonomous` 要求每一项都有 `title`、`agent_id`、`agent_name`、`decision`（以及可选 `use_prior`）。`agent_id` 必须来自候选或调度者，避免计划指向画布以外的智能体。
