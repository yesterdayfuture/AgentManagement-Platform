# 敏感词管理与监测

按部门维护敏感词清单。一条记录可含多个词；启用后，对**智能体试运行、工作流执行、模型问答**的输入与模型输出做子串匹配（含流式与非流式）。命中后任务以 `denied` 结束，并提示触发了哪个词。

实现：`backend/app/services/sensitive.py`、`backend/app/api/routers/sensitive_words.py`、`gateway` 流式补全中的监测；界面 `frontend/src/views/SensitiveWords.vue`。

---

## 管理界面

页面：`/sensitive-words`（导航「安全与治理 → 敏感词」）。交互与记忆、技能等 Desk 列表一致：搜索、分页、新建、查看、编辑、删除、批量删除。

| 字段 | 说明 |
|---|---|
| 名称 | 清单名称 |
| 敏感词 | 多个词，顿号 / 逗号 / 分号 / 换行分隔 |
| 启用 | 关闭后该清单不参与监测 |
| 部门 | 平台管理员新建时可指定；普通构建者写入当前部门 |

权限：列表 `viewer+`；写操作 `builder+`。数据按部门隔离（平台管理员可看各部门）。

---

## 监测范围

| 入口 | 输入 | 输出（非流式） | 输出（流式） |
|---|---|---|---|
| 智能体 `/api/agents/{id}/run` | ✓ | ✓ | ✓ |
| 工作流 `/api/workflows/{id}/run` | ✓ | ✓ | ✓ |
| 模型问答 `/api/chats/{id}/messages` | ✓（经智能体） | ✓ | ✓ |

词表来自当前空间所有**已启用**清单的合并；较长的词优先匹配（便于命中更具体的短语）。

与空间治理里的「禁止词 / 脱敏」不同：治理策略改写输入上下文；敏感词清单在执行层拦截，并结束任务。

## 命中行为

提示文案固定为：`触发敏感词「{词}」，已停止输出`。

### 输入命中

在进入模型循环前检查用户原文（及对话历史）。命中则抛出拒绝，接口返回错误详情（如 HTTP 400），**不会**调用模型。

### 输出命中 · 非流式

模型整段返回后检查。命中则结果正文为「已生成正文 + 换行 + 停止说明」（若尚无正文则仅停止说明），`status` 为 `denied`，智能体 / 工作流停止后续节点。

### 输出命中 · 流式

边推送边累积监测：

1. **保留**已经推给前端的正文（**不下发**用于清空界面的 `reset`）。
2. 追加一行停止说明（`delta`）。
3. 结束本轮；落库内容与界面一致：已输出正文 + 停止说明；`status=denied`。

工具轮次里、因工具调用而清空已推正文的 `reset`（与敏感词无关）行为不变。

## 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/sensitive-words` | 列表（Desk 分页 / 关键字） |
| POST | `/api/sensitive-words` | 新建。正文含 `name`、`words` 或 `words_text`、`enabled`；可选 `space_id` |
| PATCH | `/api/sensitive-words/{id}` | 改名称、词表、启用 |
| DELETE | `/api/sensitive-words/{id}` | 删除 |
| POST | `/api/sensitive-words/bulk-delete` | 批量删除，`{ "ids": [...] }` |

表：`sensitive_word_lists`（`words_json` 存词数组）。

---

## 联调提示

- 测**输入**拦截：请求里直接包含完整敏感词。
- 测**输出**拦截：提示词里不要出现完整敏感词，可让模型把分段拼成完整词再输出（否则会在输入阶段就被拦下）。
- 流式验收：命中后界面上应仍能看到命中前的片段，末尾多一行停止说明，且类型序列中不应出现因敏感词而发的 `reset`。
